# v0.4.0 — 可选步骤、异步执行与结果持久化

> 发布时间：2026-09-27

本版本聚焦"长耗时步骤"的体验与正确性：步骤 9/10/11 改为**可选（默认关闭）**、
执行过程**不再阻塞界面**、扫描结果**全部持久化**，并新增**临时软件源加速**。
同时修复了若干"看起来卡住""伪成功""中断不回滚"的真实缺陷。

---

## 一、新增功能

### 1. 可选步骤（9 / 10 / 11）默认关闭

- 步骤 9（自动安全更新）、10（安全扫描）、11（日志与审计增强）需要联网安装软件、耗时较长，
  现在**默认不勾选**，只有用户主动勾选才会执行。
- TUI 步骤列表与 CLI 选择列表均显示 `（可选·耗时）` 标记，帮助面板给出说明。
- CLI/TUI 均新增 `a` 键：全选 / 取消全选（可选步骤除外）。

### 2. 异步执行与实时进度

- 所有步骤在**后台线程**执行，界面保持响应：显示当前步骤、进度、**已耗时**、旋转指示器，
  并**实时尾随命令输出**（apt / lynis / aide 的输出来自各自的实时日志文件）。
- 每个长耗时命令都有**超时上限**（apt 更新/安装 15 分钟、lynis 15 分钟、aide 30 分钟），
  超时自动终止并明确报告，不再无限等待。
- CLI 模式同样实时输出每一步的执行日志与结果。

### 3. Ctrl+C 中断真正可用（TUI）

- **修复**：raw 模式下终端不再产生 `SIGINT`，此前 TUI 中 `Ctrl+C` 完全无效，
  且事件循环被同步执行阻塞，用户无法中断任何卡住的步骤。现在由界面直接捕获按键：
  终止当前子进程 → **回滚所有已注册修改** → 停止后续步骤。
- **修复**：中断路径此前只打印"[中断] …回退"却**没有真正执行回滚**（README 与日志文案与实际不符），现已补齐。

### 4. 扫描结果持久化

新增报告目录（`/var/log/u2secure/`，不可写时回退 `./u2secure-reports/`）：

- `lynis-<时间戳>.log` / `.dat`：lynis 完整输出与机器可读报告
- `logwatch-<日期>.txt`：日志审计报告
- `aide-init-<时间戳>.log`、`aide-check-<日期>.log`：完整性基线初始化与每日检查
- `steps/NN-<步骤>.log`：每个步骤的实时命令输出
- `mirror-<时间戳>.log`：临时软件源预热日志

步骤结果摘要与结果页都会给出**报告路径**与查看方式（`less <path>`）。

### 5. 临时软件源加速

运行前（仅当勾选的步骤涉及安装软件包时）可选择：

1. 原始软件源（默认，不做任何改动）
2. 清华大学 TUNA 镜像（显示探测延迟）
3. 中国科学技术大学镜像（显示探测延迟）

**不修改系统任何文件**：apt 通过 `-o Dir::Etc::sourcelist=… -o APT::Get::List-Cleanup=0` 使用临时源，
dnf/yum 通过 `--setopt=reposdir=…` 使用临时 repo；临时目录随运行结束自动清理。
仅改写已知上游主机，自建源不受影响；预热失败自动回退原始源。

## 二、修复

| 问题 | 说明 |
|------|------|
| 步骤 10/11 状态恒为 ❌ | `AuditReport` 未包含 lynis/logwatch/aide 检测，导致每次都被默认勾选；现改为单一真值来源 |
| 步骤 10 引入第三方源 | 改用发行版官方源安装 lynis，不再使用已废弃的 `apt-key` 与 CISOfy 第三方源（外网不通时空转数分钟） |
| 步骤 10 结果不可读 | 改为解析 `lynis-report.dat`，输出**加固指数 / 警告数 / 建议数**，并区分"发现告警（退出码 78）"与真正失败 |
| 步骤 11 伪成功 | 安装后逐项校验可执行文件，`PackageManager::Unknown` 明确跳过，不再无条件返回成功 |
| 步骤 11 覆盖发行版文件 | 不再覆盖 `/etc/cron.daily/00logwatch`；改为按需创建 `99u2secure-*`，并备份 + 注册回滚 |
| 步骤 11 初始化策略 | 仅在缺少 aide 数据库时初始化（保留既有基线），兼容 Debian `aideinit` 与 RHEL `aide --init` |
| 步骤 9 非 Debian 报错 | 由"返回错误触发全局回滚"改为明确的"跳过" |
| 未纳管的文件修改 | `/etc/apt/apt.conf.d/20auto-upgrades`、`/etc/fail2ban/jail.local` 等写入前备份并注册回滚 |
| 步骤 12 无条件重启 | 比较 `sshd_config` 与 sshd 进程启动时间，配置未变更时跳过重启（状态也不再恒为 ❌） |
| 跳过被计入失败 | 结果统计改为**成功 / 跳过 / 失败**三态，TUI 与 CLI 语义一致 |
| TUI 公钥粘贴 panic | `&value[..50]` 字节切片在多字节字符下会 panic，改为按 char 边界截断；`get_key_fingerprint` 同类问题一并修复 |
| 步骤 2 伪成功 | `usermod -aG sudo` 失败不再被忽略，并支持 RHEL 的 `wheel` 组 |
| 日志路径写死 | CLI 结尾显示实际写入的日志路径（无权限时会回退到当前目录） |
| 失败即全量回滚 | 可选步骤失败不再触发全局回滚，避免"装不上 lynis 就把已加固的 SSH 配置全部退回" |

## 三、内部改进

- 新增 `application::job::StepRunner`：CLI 与 TUI 共用同一套执行策略（顺序、失败、中断、镜像、产物），
  消除两套编排逻辑；提供可注入的测试缝（`run_steps` / `spawn_steps`）。
- `main.rs` 直接复用 lib crate，移除重复的模块树（减少一次完整编译）。
- 清理死代码：`HardeningStep::check_status`（12 处实现）、`AuditReport::summary_lines`、
  TUI 同步执行函数、未使用的 i18n 键 120+ 条。
- 测试从 40 个增加到 74 个，新增执行策略、异步取消、镜像改写、lynis 报告解析、报告目录等用例。

## 四、升级提示

- 步骤 9/10/11 不再默认执行；如需自动安全更新、安全扫描与日志审计，请在步骤列表中**手动勾选**。
- 完整扫描结果现在位于 `/var/log/u2secure/`，可使用 `less` 查看。
- 从 v0.3.x 升级无需额外迁移操作。
