## 一、执行计划确认

CLI/TUI 的单项、批量与镜像失败后的再次尝试，在步骤参数和镜像选择完成后显示统一计划，
用户可以确认执行、返回修改或取消。步骤顺序和去重复用执行器的计划函数；确认前不启动执行器或镜像预热。

计划列出目标用户、端口、密钥操作类型、镜像及 SSH 生效授权，不显示公钥正文或完整参数。
同批重复密钥生成、SSH 重启和 UFW 延后均说明运行时条件，不将预览写成已经完成的结果。
返回修改会丢弃旧确认；再次尝试前仍需复核，取消不能撤销先前已发生的镜像预热或缓存更新。

## 二、SSH 连接上下文检查

CLI 审计后可选择检查一组连接条件，TUI 在未执行批次时按 `c` 进入；任一输入留空可取消。
显式提供用户名、来源 IP、来源主机名或地址、本地地址和端口，再确认执行只读查询。

程序校验输入并使用 argv 调用 `sshd -T -f <配置> -C <连接条件>`，由 OpenSSH 处理 Include/Match。
结果显示输入条件、PasswordAuthentication、KbdInteractiveAuthentication、PermitRootLogin 原值及基线对比。
命令沿用 5 秒和 1 MiB 的内存采集限制；输入、配置、命令或采集错误明确展示，不回退全局值伪装成功。

单组求值不改变全局审计的 Partial、不改变默认步骤选择，也不修改系统配置或服务。
这不检查运行中配置、账户、PAM、密钥、网络或真实登录，不提供远程连通性保证。

## 三、批次结果与配置备份索引

进入执行器并正常收尾的每个批次，在既有报告目录生成独立 `batch-<批次标识>.json`（0600），
CLI/TUI 显示保存路径或独立错误。schema 1 包含批次时间、稳定步骤 ID、未执行步骤、原步骤结局、
最终处置、已登记撤销的执行顺序与结果、配置/备份对应关系、恢复/清理结果及收尾时的保留观察。

核心失败、中断、可选失败、镜像准备失败和 SSH 生效尝试后的保留分别表达；
先前的 changed 不证明修改最终保留，撤销回调返回成功也不证明所有系统动作均已恢复。
记录不保存配置、密钥、完整参数或命令原始输出；日志和扫描产物仅为可能共享的路径引用。

写入、刷新、同步或发布失败单独报告，不改变既有提交/回退决定。
确认前取消不生成记录；独立 audit 继续不创建默认文件。
备份状态只代表收尾时观察，手动使用前需检查现状；密钥临时备份仍按原策略清理。
不提供自动恢复、跨进程撤销、崩溃续跑或历史检索界面。

## 四、系统待重启提示

系统更新成功后、交互审计及独立 text/JSON 审计共用只读探测，TUI 在系统更新详情中显示来源与限制。
按 os-release 的精确 ID 识别 Debian/Ubuntu，分别检查 `/run/reboot-required` 和 `/var/run/reboot-required`；
其它发行版明确显示不支持，仅有 ID_LIKE 不冒充受支持平台。

结果区分发现提示、未发现受支持提示和无法判断，不读取包清单、不安装诊断工具、不执行或安排重启。
未发现标记不证明无需重启；该提示不改变 APT 缓存状态或 SSH 服务重启语义。
独立审计探测失败显式返回错误；已成功系统更新后的辅助探测失败保留更新成功结果并展示诊断。

## 五、兼容性

| 接口或流程 | 变化 |
|------------|------|
| CLI/TUI | 执行前增加计划确认；新增显式 SSH 上下文查询入口；执行后显示批次记录路径 |
| `AuditReport` | 新增 `reboot_hint` 字段，直接构造结构体的 Rust 调用方需补齐 |
| `JobEvent` | 新增 `BatchRecord` 事件，穷尽匹配的 Rust 调用方需处理 |
| 独立 audit JSON schema 1 | `system-update.details` 兼容新增 `reboot_hint`；原状态判定不变 |
| 批次 JSON schema 1 | 新的独立文件契约，与只读审计 JSON 分开 |
| 平台 | 继续只发布 Linux x86_64/ARM64 的 GNU 与 musl 四个目标，npm 仍选择 GNU 资产 |

README 同步更新功能入口、记录路径及版本信息，并修正旧文档中的 UFW 撤销、端口修改顺序、
SSH 生效边界和镜像失败描述；这些文档修正未改变对应执行策略。
